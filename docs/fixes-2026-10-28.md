# Исправления повторного аудита — 28 октября 2026

Исправлены все шесть багов и оба места с лишней сложностью из
[повторного аудита](review-2026-10-28.md). Изменения применены поверх
существовавшего рабочего дерева; новые библиотечные зависимости не добавлялись.

## Передача и подготовка прошивки

- **B1:** блокирующая запись FileData может уступить обработку входящему
  AEA-запросу, когда окно приёма образа закрыто. Ответ уходит по отдельному
  DataPort, после чего передача продолжается с учётом уже отправленных байтов.
  Незавершённый plist дописывается перед inline-ответом ключа; ответ через
  отдельный порт не требует предварительно дописывать буфер образа.
- **B3:** общий разбор FTAB/UARP читает ограниченные индексы по их настоящим
  смещениям. Потоковая проверка временно сохраняет контейнер на диск и
  проверяет также payload поздних вложенных таблиц. Обычные файлы и большие
  файловые системы продолжают проверяться потоком без такой копии.
- **B4:** сжатые OS-образы подготавливаются до первого boot upload и
  StartRestore. Свободное место, запись временного файла и ZIP CRC проверяются
  заранее. Готовый файл используется повторно для ASR и FileData;
  параллельные запросы получают независимые файловые курсоры. Временные
  файлы удаляются после освобождения последнего использующего их контекста.

## GUI, USB и каталоги

- **B2:** занятый mutex журнала отличается от пустой очереди. GUI сохраняет
  завершившуюся задачу до успешного переноса последних записей. Итоговая
  запись и flush выполняются в рабочем потоке до Finished. Длительность,
  предупреждения об активации, перезагрузке и неполном журнале сохранены.
- **B5:** недоступный или отключившийся соседний USB-кандидат не обрывает
  поиск целевого ECID и не скрывает исправные устройства при сканировании.
  Причина ошибки известного целевого устройства сохраняется; если прочитать
  не удалось никого, сканирование возвращает диагностику отказов.
- **B6:** ошибки загрузки, декодирования и метаданных каждого каталога
  обрабатываются отдельно. При наличии корректного подходящего релиза
  операция продолжается; конфликты доступных каталогов по-прежнему запрещены.
  При отсутствии результата возвращаются также исходные причины отказов.
- **O1:** найденный в GUI Release передаётся в операцию и используется через
  существующий ensure_cached. Повторная загрузка каталогов для уже выбранного
  релиза убрана. Кнопка «Обновить» явно обновляет выбор; CLI и операции без
  предварительного выбора сохраняют автоматический подбор.
- **O2:** конфигурация HTTP строится до создания TSS Agent. Неиспользуемый
  промежуточный Agent и его обработчик отмены удалены. Раздельное доверие
  TSS и HTTPS-прокси сохранено.

## Регрессионные тесты

Постоянные проверки находятся в `tests/unit/restore.rs`, `tests/unit/gui.rs`,
`tests/unit/ipsw.rs`, `tests/unit/ipsw/verify.rs`, `tests/unit/catalog.rs`
и `tests/unit/usb_enumeration.rs`. Протокольный тест параллельного ASR
проверяет использование подготовленного образа независимым ZIP-контекстом.

Тест AEA проверяет реальное продолжение передачи через подставной mux,
полное содержимое FileData, отсутствие повторённых байтов и правильный ключ.
Для GUI проверяется сохранение последней ERROR-записи при занятом mutex.
Для FTAB один корректный файл проверяется целиком и потоком, причём вложенная
таблица начинается после 3 MiB; проверены внешние FTAB и UARP. Для сжатого OS проверяются CRC, ошибка
временного хранилища, повторное использование файла, независимость курсоров
и очистка временного файла.
