# Область проверки

Документ описывает воспроизводимые проверки проекта и пределы их выводов.
Команда `plan` ссылается на этот файл в поле `hardware_validation_report`.

## Автоматические проверки

Модульные и интеграционные тесты используют локальные IPSW/ZIP, фикстуры plist,
DER и сертификатов, подставные USB-транспорты, TCP-серверы и TLS-прокси на loopback.
Они проверяют форматы, контрольные суммы, запросы подписи,
переподключения, частичные записи и чтения, ошибки и отображение событий в GUI.

Сетевые фикстуры не требуют соединения с Apple. Тесты GUI создают контекст egui
без открытия пользовательского окна. Windows-модули содержат отдельные тесты
упаковки CAB, реестровых форматов и вызовов системных API с подставными функциями.

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets --all-features -- -D warnings
cargo test --locked --all-features
cargo check --locked --target x86_64-pc-windows-gnu --all-targets --all-features
```

Для последней команды нужен установленный Rust target. Компиляция под Windows
проверяет типы и условно компилируемый код, но не выполняет Windows-тесты.
Проверки CI также запускаются на Windows; локальная компиляция не доказывает
успешность конкретного запуска CI.

## Ограничения

После исправлений 28 октября регрессионные проверки дополнительно покрывают
глубокие XML/binary plist, Win32 device removal, CRC stored OS после seek,
HTTP inactivity timeout, публикацию partial без перезаписи и перегрузку журнала.
Подробности изменений: [аудит 28 октября](audit-2026-10-28.md).
Дополнительные регрессии покрывают поздний AEA key request при закрытом окне,
продолжение FileData без повтора байтов, занятой mutex журнала при завершении,
вложенный FTAB за пределами первого блока, подготовку сжатых файловых систем,
ошибку соседнего USB-устройства и отказ одного каталога Apple.
Подробности: [исправления повторного аудита](fixes-2026-10-28.md).

В ходе аудита 26 октября 2026 года физическое восстановление Mac, установка
драйверов и раздача интернета через реальный USB не выполнялись. Успех тестов
подтверждает проверенные программные сценарии; аппаратный результат зависит
от модели Mac, прошивки, кабеля, USB-контроллера и драйверов хоста.

`verify` отдельно перечисляет AEA-компоненты, чьи контрольные суммы описывают
расшифрованное содержимое. Проверка полного IPSW по доверенной внешней сумме
отмечается полем `archive_checksum_verified`.

`plan` проверяет метаданные, boot-компоненты и построение этапов iBoot. Он
не получает TSS tickets, не запускает restoreOS и не выполняет восстановление.
Поля `hardware_restore_validated: false` и `runtime_operations_known: false`
сохраняют это различие в машинном отчёте.

Синтетические throughput-тесты, большой ZIP64-тест и проверка реального HTTPS
доступа к TSS помечены `ignored` и не входят в обычный прогон. Их следует
запускать явно по имени; `--ignored` включает и обращение к Apple, и
ресурсоёмкую проверку ZIP64 размером более 5 ГиБ.
