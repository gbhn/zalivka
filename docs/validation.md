# Проверка восстановления

## Подтверждённый физический запуск

В пользовательском журнале от 25 октября 2026 года Mac подтвердил успешное
восстановление. Устройство: MacBookAir10,1, j313ap, CPID 0x8103, BDID 0x26.
IPSW: macOS 27.0.1, сборка 26A434. Хост: Windows, режим Erase.

Зафиксированы успешные FDR checkpoints, `await_update_appletcon`, полная
передача ASR 10,50 ГиБ, подпись и передача Cryptex1, завершение `install_splat`.
На 14:07.641 записано подтверждение успешного восстановления от Mac; на
14:07.734 — завершение с переходом к раздаче интернета по USB.
Источник: пользовательский журнал `Pasted text.txt`, переданный в чат после
сборки `zalivka-metadata.exe`. Персональные ECID и nonce сюда не переносятся.

Это подтверждение протокола для одного физического запуска. Проверка загрузки
установленной macOS пользователем, Revive/Update, T2 и другие модели или сборки
IPSW этим журналом не подтверждены.

## Автоматические проверки

Сценарии boot, TSS, аттестации, ASR, async-запросов, обработки ошибок,
потери соединения и окончательного статуса покрываются тестами на mock transport.
В fixtures сохранены обезличенные запросы реального запуска, включая FDR,
GlobalManifest и Cryptex1. Тесты не заменяют физическую проверку каждой модели.

Workflow `.github/workflows/check.yml` запускает форматирование, Clippy и весь
обычный набор тестов на Windows и Linux. Локально используются те же команды
из README; Windows-специфичные тесты запускаются нативным Windows Cargo.
Число тестов зависит от платформы и меняется вместе с набором проверок;
фиксированное число здесь не используется как критерий готовности.
Тяжёлые бенчмарки, проверка большого ZIP64 и сетевой тест TSS исключены
из обычного запуска через `#[ignore]`.

`hardware_restore_validated=false` в результате `plan` относится к этой
офлайн-проверке: команда не выполняет восстановление. Ссылка на этот отчёт
указывает, какие физические результаты известны проекту; таблицей выбора
совместимых устройств она не является.
