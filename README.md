# Zalivka

Нативное приложение на Rust для восстановления Apple Silicon и T2 Mac через USB
из Windows. В одном EXE доступны графический интерфейс, CLI и раздача интернета
по USB после восстановления.

Список компонентов выбирается по метаданным IPSW, а запросы после загрузки
службы восстановления поступают от Mac. Таблиц совместимости моделей и
контроллеров нет. При недостатке данных программа явно отказывает.

## Проверенные сценарии

Mac подтвердил успешное Erase-восстановление MacBookAir10,1 / j313ap / 26A434
в предоставленном журнале. Подробности и границы проверки находятся в
[отчёте проверки](docs/validation.md). Revive, T2 и остальные модели не считаются
проверенными этим запуском. Движок остаётся экспериментальным.

Erase удаляет данные Mac. GUI требует подтверждение перед началом.
Полное восстановление не запускается командами `inspect`, `verify` и офлайн `plan`.

## Сборка и проверки

Нужны Rust и инструменты компилятора для выбранного target. В PowerShell:

```powershell
.\scripts\build.ps1 -Check
```

Скрипт выполняет форматирование, Clippy и тесты, затем публикует EXE в
`artifacts/` с версией и уникальным идентификатором сборки в имени. Рядом
сохраняется JSON с SHA-256. Запускайте опубликованный файл: staging-копия Cargo
в `target/build/` должна оставаться свободной для следующей сборки.
Полные параметры приведены в [инструкции сборки](scripts/README.md).

Идентификатор содержит Git revision, отметку изменённых исходников и fingerprint
исходников, встроенных ресурсов, компилятора, target, профиля и Cargo features.
Время создания отличает повторные компиляции одних исходников: Windows linker
может создать разные двоичные файлы при одинаковом исходном коде.
Он выводится в `--version`, интерфейсе и начале журнала. SHA-256 опубликованного
EXE позволяет отличить двоичные файлы, даже если их исходники одинаковы.
Повторный выпуск без изменений использует кэш и сохраняет тот же ID. Обновление
служебного Git index само по себе пересборку не запускает.

Для отдельных проверок:

```text
cargo fmt --all -- --check
cargo clippy --locked --all-targets --all-features -- -D warnings
cargo test --locked --all-features
```

Те же команды выполняет GitHub Actions на Windows и Linux. Исключённые по
умолчанию тесты — тяжёлые бенчмарки, проверка большого ZIP64 и сетевой тест TSS.
Обычный набор не прошивает физическое устройство.

## CLI

```text
zalivka --help
zalivka inspect firmware.ipsw --json
zalivka plan firmware.ipsw --identity 3
zalivka verify firmware.ipsw
```

Индекс в примере `plan` задаётся явно; нужную identity можно найти через `inspect`.
`plan` проверяет загрузочные компоненты выбранного IPSW, но не подтверждает
успешное восстановление на оборудовании. Для запуска интерфейса используйте `gui`.

Описание реализации: [восстановление по метаданным](docs/dynamic-restore.md),
[аттестация и eCfg](docs/restore-attestation-and-ecfg.md),
[восстановление USB-сети после Stall](docs/usb-internet-stall.md).
