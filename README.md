# Zalivka

Экспериментальный Rust-клиент для восстановления прошивки Apple Silicon и T2 Mac
через DFU. В проект входят CLI и необязательный настольный интерфейс на egui.
Подключение к USB прямое; для обмена с устройством не используется usbmuxd.

## Сборка и запуск

Требуются Rust 1.99 или новее и инструменты компилятора для выбранной платформы.
Подробности Windows-сборки и публикации EXE: [scripts/README.md](scripts/README.md).

```sh
cargo build --locked --features gui
cargo run --locked --features gui -- gui
```

CLI доступен и без feature `gui`:

```sh
cargo run --locked -- --help
cargo run --locked -- detect --json
```

## Работа с локальной прошивкой

```sh
zalivka inspect firmware.ipsw --json
zalivka verify firmware.ipsw
zalivka plan firmware.ipsw --identity 0
```

`inspect` выводит идентификаторы сборки и доступные build identities. `verify`
проверяет ZIP-потоки, CRC и поддерживаемые контрольные суммы компонентов.
Для проверки полного архива передайте `--checksum` с доверенным SHA-1 или SHA-256.
Контрольные суммы расшифрованного содержимого AEA учитываются отдельно в отчёте.

`plan --identity` работает без USB и сети. Для проверки соответствия подключённому
Mac используйте `plan --ecid HEX_ECID`; ECID задаётся шестнадцатеричным числом.
Эти два способа выбора взаимоисключающие. `--revive` выбирает проверку Update identity.
План не подтверждает успешное аппаратное восстановление.

## Команды для подключённого Mac

```text
zalivka doctor
zalivka drivers status
zalivka fetch --ecid HEX_ECID
zalivka revive firmware.ipsw --ecid HEX_ECID
zalivka restore firmware.ipsw --ecid HEX_ECID --erase
```

Замените `HEX_ECID` значением из `detect`. Restore стирает данные; Revive требует
Update identity и не переключается на Erase при её отсутствии. Если путь IPSW
не передан, прошивка выбирается из каталога Apple и загружается в кэш.
`--firmware-dir` задаёт каталог автоматической загрузки и не совмещается с локальным IPSW.

В Windows запускайте Zalivka обычным способом под своей пользовательской учётной
записью. Сетевые запросы используют её настройки прокси, включая PAC/WPAD.
Если прокси отвечает `407` и предлагает `Negotiate` или `NTLM`, программа
автоматически авторизуется через Windows SSPI с учётными данными текущего входа.
Вводить или сохранять доменный пароль не требуется. Это действует для запросов
прошивки и ресурсов Apple, а также FDR при восстановлении. Повышение прав
отдельно запрашивается для операций с драйверами. Журнал показывает учётную запись,
схему и результат авторизации прокси; сами токены авторизации в него не записываются.
Сертификаты HTTPS в Windows проверяются системным механизмом Windows, который
учитывает корни текущего пользователя, компьютера и корпоративные корни. Это
относится и к ресурсам Apple, и к HTTPS-прокси. Проверки имени сервера, цепочки
и срока действия остаются включены. Для TSS дополнительно поддерживается
встроенный корень частной PKI Apple, без добавления его к доверию CDN или прокси.

Для FDR TLS-соединение с Apple устанавливает сам восстанавливаемый Mac через
туннель Zalivka. Корпоративные корни Windows к этому соединению не применяются.
Прокси должен разрешать CONNECT к `tbsc.apple.com:443` без подмены сертификатов
(HTTPS/SSL Inspection). Требования к остальным адресам описаны в
[документации Apple для корпоративных сетей](https://support.apple.com/101555).

В Windows `drivers prepare` устанавливает недостающие драйверы и останавливает
Apple Mobile Device Service. Подготовка пишет в журнал сведения о правах и учётной
записи процесса, этапах распаковки и установки, кодах ошибок Windows и итоговой
проверке драйверов. Сообщения скрытого процесса UAC передаются в тот же журнал
интерфейса; при ошибке установки добавляются новые записи `setupapi.dev.log`.
В терминале подробный журнал включён по умолчанию.

Наличие пакета проверяется через SetupAPI, без поиска папок по имени в DriverStore.
После подготовки программа проверяет выбранный драйвер и реальный доступ к USB-интерфейсам
подключённых устройств с правами исходного процесса. Если Mac отключён или Windows требует
перезагрузку, журнал отдельно сообщает, что пакет установлен, а проверка USB-доступа отложена.

Если после восстановления Windows перестала обнаруживать Mac, в настройках GUI
есть **«Сбросить USB-драйверы Apple»**, в CLI — `zalivka drivers reset`.
С подтверждением UAC команда останавливает службу Apple, удаляет записи USB-устройств
Apple в режимах DFU / Recovery / Restore, включая отключённые, повторно устанавливает
встроенный подписанный пакет и запускает поиск устройств. Пакеты из DriverStore
не удаляются. На время сброса подключённые устройства Apple в этих режимах отключаются.
Кнопка доступна, когда операция Zalivka не запущена. После сброса подключите Mac
заново и введите его в DFU; если Windows запросила перезагрузку, сначала выполните её.
Сброс привязок драйвера не гарантирует устранение аппаратного зависания USB-порта.
Журналы интерфейса сохраняются в `%LOCALAPPDATA%\zalivka\logs`.

GUI вызывает операции библиотеки напрямую в фоновом потоке, без запуска CLI и
чтения stdout/stderr. Прогресс и сообщения передаются как Rust-события. Отдельный
процесс используется только для операций с драйверами через Windows UAC.

TRACE включён по умолчанию для диагностики USB/usbmux, plist, HTTP/TSS, согласования
FDR, SOCKS и полных hex-дампов FDR в обе стороны. Записи содержат канал,
направление TX/RX и смещение; байты выводятся без обрезки, порциями до 64 байт.
Во время передачи содержимого прошивки (ASR, DFU/Recovery, FileData, Bootability
и firmware-updater) TRACE на потоке передачи отключён: ни байты, ни plist с
бинарным содержимым, ни сообщения на каждый USB-пакет не записываются. Прогресс,
ошибки и итоговая статистика остаются; параллельные соединения FDR сохраняют
полный TRACE.
Hex-дампы и подробные plist форматируются в отдельном потоке журнала; рабочие
потоки передают ему копию исходных данных без ожидания диска или терминала.
Запись буферизуется, обновления окна объединяются. При завершении операции,
выходе из CLI и сохранении журнала очередь дописывается полностью. Копирование
данных в очередь всё ещё расходует немного CPU и памяти; полная запись TRACE
не может иметь строго нулевую стоимость.
В GUI обычный вид журнала показывает INFO, WARN и ERROR; **«Технические подробности»**
открывает DEBUG и TRACE, в том числе уже собранные записи. На диске сохраняется
полный журнал, в окне — ограниченная история; дампы не вытесняют обычные сообщения.
В CLI подробный журнал выводится в stderr, а отчёты JSON — в stdout. Флаги
`--trace`, `--verbose` и обязательный `--experimental` удалены. TRACE создаёт большой
журнал с содержимым обмена, в том числе данными устройства.

После завершения Restore или Revive операция заканчивается. Доступ к сети нужен
компьютеру с Zalivka для загрузки прошивки и обмена с Apple при восстановлении.
Если после перезапуска появился экран **«Активировать Mac»**, подключите сам Mac
к Wi-Fi или Ethernet и завершите активацию. Интернет на компьютере с Zalivka
не заменяет подключение Mac на этом этапе. Успешный статус Restore подтверждает
завершение восстановления, но не подтверждает активацию. Если Mac сообщил об
ошибке получения UCRT/DCRT, итоговое уведомление сохраняет предупреждение
и подсказку об активации даже при успешном статусе восстановления.

## Локализация

Интерфейс выбирает язык системы: русский для русской локали, английский для
английской или неподдерживаемой. В **Settings → Language / Настройки → Язык** можно
выбрать язык вручную или вернуть автоматический выбор. Журналы и диагностика CLI
всегда используют английские тексты независимо от языка интерфейса; данные устройств
и имена файлов сохраняются без изменений.

Английский и русский встроены в EXE. Дополнительные языки загружаются из JSON-файлов
в папке `locales` рядом с EXE или в `%LOCALAPPDATA%\zalivka\locales`, без изменения
кода и пересборки. Новые каталоги появляются после перезапуска; отсутствующие
переводы заменяются английскими. Формат и инструкция: [locales/README.md](locales/README.md).
