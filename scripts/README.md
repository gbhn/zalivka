# Сборка

Для Windows нужны Rust 1.89 или новее и инструменты компилятора для выбранного
Rust target. Команда `cargo` должна быть доступна в `PATH`.

Из корня проекта в PowerShell:

```powershell
.\scripts\build.ps1
```

Если запуск `.ps1` запрещён политикой PowerShell, можно разрешить его только
для этого процесса:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

По умолчанию собирается release-версия с GUI и командами CLI. При обычной
конфигурации Cargo опубликованный EXE находится в `artifacts\` и содержит
версию и идентификатор сборки в имени, например `zalivka-0.1.0+<build-id>.exe`.
Скрипт печатает полный путь. Рядом сохраняется `.exe.json` с SHA-256, версией
компилятора, target, профилем и Cargo features. Идентификатор также виден через
`--version`, в интерфейсе и начале журнала.
Встроенные пакеты драйверов включаются в исполняемый файл при компиляции.

Дополнительные варианты:

```powershell
# Сначала форматирование, Clippy и нативные тесты, затем сборка
.\scripts\build.ps1 -Check

# Отладочная сборка с отдельным fingerprint
.\scripts\build.ps1 -DebugBuild

# Сборка только CLI
.\scripts\build.ps1 -CliOnly

# Сборка для явно указанного target
.\scripts\build.ps1 -Target aarch64-pc-windows-msvc
```

Промежуточные результаты Cargo хранятся в `target\build\`, для явного target —
в его подпапке. Запускайте копию из `artifacts`, чтобы запущенный EXE не блокировал
повторную сборку. Старые опубликованные версии не перезаписываются: при совпадении
имени проверяется SHA-256; другой файл с тем же ID считается ошибкой.
Target и необходимые инструменты компилятора должны быть установлены заранее.
`-Check` выполняет проверки для текущего хоста; `-Target` задаёт target самой сборки.

Скрипт можно вызывать по полному пути из любой папки. При ошибке сборки он
возвращает код завершения Cargo. Зависимости берутся из `Cargo.lock`.
Для Git revision нужен доступный `git`; без него версия содержит `unknown`,
но fingerprint исходников, target, профиля, features и компилятора остаётся.
